# 絵の 方針(アートディレクション)

このファイルは **絵を 描く人(または 絵を 描く AI)への 指示書**です。
「何を 何個 描くか」の 一覧は [ART_ASSET_LIST.md](./ART_ASSET_LIST.md)(自動生成)に あります。
先に この ファイルを 読んで、それから 一覧を 見てください。

---

## 0. いまの じょうきょうと ゴール

いまの 絵は **TypeScript の コードで しかく・まる・さんかくを ならべて** 描いています
(`src/ui/icons/*.ts`)。動くし 軽いのですが、**絵として 品質が 低い**のが 問題です。
これを 差しかえるのが この 仕事の ゴールです。

- 差しかえるのは **見た目だけ**。ゲームの ルールや 配置は 変えません
- ですから **1つずつ 差しかえられます**。202個 ぜんぶ 揃うまで 待つ 必要は ありません
- 古い コード描画は しばらく 残します(SVG が ない かたちは これまで どおり 出る)

---

## 1. だれの ための 絵か

| 項目 | 内容 |
|---|---|
| 遊ぶ人 | **4〜8歳**。ひらがなを 読めない 子も いる |
| 端末 | iPad / iPhone。よこ480 × たて800 の 画面を 拡大して 表示 |
| 出る 大きさ | **20〜58px**。ほとんどが **26〜46px** |
| 見る 時間 | **1秒**。ゲーム中に ちらっと 見て 何か わかる 必要が ある |

これが すべての 判断の 土台です。「よく 見ると 上手い 絵」は この 用途では 失敗です。

---

## 2. 品質の 合格ライン(これで 判定します)

新しい 絵は 次の 4つを ぜんぶ 満たすこと。

1. **32px に 縮めても 何か わかる**
   縮小して 見て 「茶色い かたまり」に なったら やり直し。
2. **名前を 見ずに 何か 言える**
   子供に 見せて 「さかな」「おうち」と 言えること。
   `くり` と `いも`、`わん` と `さら` のように **似た ものと 区別が つく**こと。
3. **他の 絵と ならべて 家族に 見える**
   線の 太さ・目の 描き方・角の 丸みが そろっていること。1つだけ 浮いたら やり直し。
4. **どの 色に しても 成立する**
   同じ かたちを 20色で 使い回します(§5)。特定の 色前提の 描き方は だめ。

## 3. 絵柄の 大方針

**「厚紙を 切って 貼った 絵本」**を 目指します。フェルトや 折り紙の 工作に 近い 感じ。

### やること

- **平ぬり**。1つの 面は 1色
- **太い ふちどり**。かたちの 外側に こい色の 線(§5 の `#DARK`)。
  64 の 座標系で **線幅 2.4〜3**。細い 線は 縮小で 消えます
- **単純な シルエット**。まず 遠くから 見た 形が わかること。中の 模様は 最後
- **要素は 3〜6個**まで。それ以上 描くと 32px で つぶれます
- **正面 か 真横**。ななめ・パースは つけない
- **角は 丸める**。とがった 角は 「危ない/固い」ものだけ(いし・ナイフ・とりい)
- **顔は 点2つ + 口1本**。目や 口を 描きこまない。まるい 頬を 1つ 足すのは よい
- **上を 少し 明るく**。白 20〜35% の ハイライトを **1つだけ** 置いてよい

### やらないこと(見つけたら 差し戻します)

| だめ | なぜ |
|---|---|
| 写実・立体的な 陰影 | 絵柄が そろわない。子供向けに 見えない |
| グラデーション(2段より 多い) | 縮小で 濁る。SVG が 重くなる |
| 影(ドロップシャドウ)・ぼかし | 平ぬりの 方針と 合わない |
| 細い線(64座標で 1.5 未満) | 縮小で 消える |
| 文字・数字を 絵に 入れる | 読めない 子が いる。翻訳も できない |
| 目の ハイライトや まつげ | 32px では ノイズに なる |
| 実在の キャラクター・商標・ロゴ に 似た もの | 使えません |
| 3つ以上の 色を 追加 | §5 の しくみを こわす |

## 4. かたちの 仕様(SVG)

```
viewBox="0 0 64 64"
```

- **正方形 64×64**。この 中に 収める
- **セーフエリア**: 外側 3 は 空ける(**実質 58×58**)。ふちどりが 切れないように
- **中心に 置く**。左右・上下に 偏らせない(並べたとき ガタガタに 見える)
- **なるべく 枠を 使い切る**。小さく 描くと 縮小時に 見えません。
  高さか 幅の どちらかは 50 以上 使うこと
- パスの 数は **20 以下**が 目安。50 を 超えたら 描きすぎ
- `<path>` `<circle>` `<ellipse>` `<rect>` `<polygon>` `<g>` だけ 使う
- **使えない もの**: `<image>`(ラスタ埋め込み)、`<text>`、`<filter>`、`<clipPath>`、
  `<mask>`、`<use>`、外部フォント、`style` 属性の CSS 変数、アニメーション要素
- `fill` と `stroke` は **属性で** 書く(`fill="#MAIN"`)。`style="fill:..."` は 使わない
- `stroke-linejoin="round"` `stroke-linecap="round"` を 基本に する

### 最小の 例

```svg
<svg xmlns="http://www.w3.org/2000/svg" viewBox="0 0 64 64">
  <!-- いちご: さきが とがった み + みどりの がく -->
  <path d="M32 58C18 58 9 46 9 34c0-9 10-12 23-12s23 3 23 12c0 12-9 24-23 24z"
        fill="#MAIN" stroke="#DARK" stroke-width="2.6" stroke-linejoin="round"/>
  <circle cx="24" cy="34" r="1.8" fill="#DARK" opacity="0.55"/>
  <circle cx="40" cy="38" r="1.8" fill="#DARK" opacity="0.55"/>
  <circle cx="32" cy="46" r="1.8" fill="#DARK" opacity="0.55"/>
  <path d="M32 22c-6-2-12-5-14-10 6-1 11 1 14 4 3-3 8-5 14-4-2 5-8 8-14 10z"
        fill="#5AA04A" stroke="#37702C" stroke-width="2" stroke-linejoin="round"/>
  <ellipse cx="24" cy="28" rx="5" ry="3" fill="#FFFFFF" opacity="0.28"/>
</svg>
```

## 5. いろの しくみ(ここが 大事)

同じ かたちを **色を 変えて 使い回します**。
`いちご:red` `いちご:cream`(まだ 白い いちご)のように データが 指定します。
202の かたちに 対して **のべ 526の 色ちがい**が 使われています。

そこで **色ちがいは 描きません**。SVG に 2つの 合図を 書いておき、
アプリが 読みこむ ときに 置きかえます。

| 書く 文字 | 置きかわる もの | 使う ところ |
|---|---|---|
| `#MAIN` | 本体の 色 | 面の ぬり |
| `#DARK` | 本体より こい色 | ふちどり・影・点 |

**それ以外の 色は そのまま 出ます。** ですから

- 「その ものの 色」が 決まっている 部分は **直接 色を 書く**
  (はっぱの 緑・木の 茶・炎の 橙・白い 紙)
- 「色ちがいで 変わる」部分だけ `#MAIN` / `#DARK` に する

いちごの 例なら、みが `#MAIN`、がくは 緑を 直接 書く。
これで `いちご:red`(赤い実+緑のがく)も `いちご:cream`(白い実+緑のがく)も 1枚で 足ります。

### 直に 書いた 色が 「消える」わな(実際に 1件 やりました)

たね・点・すじ など **小さい しるしを パレットの 色で 直に 書くと、
その 色ちがいの ときだけ 消えます。**

> いちごの たねを `#F6E7C4` に した ところ、`いちご:cream`(まだ 白い いちご)で
> 実と たねが 同じ 色に なり、たねが 見えなくなりました。
> `いちご` が つかう 色は cream と red の 2つだけ なので、半分が 壊れていた ことに なります。

**きまり**: 小さい しるし(たね・点・すじ・もよう)は **`#DARK` に する**。
どうしても 固定色に したい ときは、その かたちが つかう 色の
`#MAIN` / `#DARK` と かぶらない 色を 選ぶこと
(その かたちが つかう 色は ART_ASSET_LIST.md の 「つかう いろ」の 欄に あります)。

これは `npm run art:check` が **自動で 見つけます**(§9-1)。

**確認の こつ**: 描いたら `#MAIN` に `cream`(`#F6E7C4`)と `dark`(`#4A4A52`)の
両方を 入れて 見ること。この 2つで 崩れなければ どの 色でも 大丈夫です。
背景は クリーム色(`#F2F7E8`)なので、**うすい 色でも ふちどりで 形が 見える**ことが 必須。

## 6. ファイルの 置き場所と 名前

```
docs/art-ref/<かたちの名前>.webp        ← 下絵(参考・512px)。アプリには 入らない
public/art/icons/<かたちの名前>.svg     ← 202個。名前は ART_ASSET_LIST.md の とおり
public/art/bg/bg-<ゲーム名>.svg         ← 59個(§7)
```

- 名前は **一覧の ファイル名と 1文字も 変えない**こと。名前で ひもづけています
- 1つの かたちに 1ファイル。色ちがいの ファイルは 作らない

### アプリ側の 読みこみ方(絵を 描く 人は 読まなくてよい)

| | アイコン | 背景 |
|---|---|---|
| どこから | バンドルに 埋めこみ | あそぶ ときに 取りに いく |

| しくみ | `src/ui/icons/svg.ts` | `src/ui/bgArt.ts` |

背景は 置くだけで 出ます。絵が ない あいだ(と 読めなかった とき)は
いままでの コード描画の 背景が そのまま 出るので、途中でも 遊べます。

**いまは 背景を 1まいも つかって いません。** 59まい 納品ずみ ですが、
実際の 画面で 見くらべた ところ いまの コード描画の ほうが よかった ため、

`art-hold/README.md` を 見て ください。

ずれる 2つ(care→defense / yatai→festival)だけ ここに 書いて あり、

## 7. 背景(せかい)の 仕様

ミニゲーム 59本の 背景。いまは コードで しかくを ならべているだけです。

```
viewBox="0 0 480 748"
```

- **場所だけ**を 描く。人・道具・食べものは **描かない**
  (それらは アイコンで 上に 置きます。二重に なります)
- 遊ぶ 面は 画面の **上60%**。ここは **すっきり**させる。
  細かい 模様は 下40%か 画面の ふちに 寄せる
- 主役の アイコンが 見えないと 困るので、**背景の コントラストは 弱め**に する
- 空・地面の 境目を はっきり させる(子供が 「地面」を 認識できるように)
- 夜の まつりは 暗い 背景で よい。ただし アイコンが 沈まない 明るさを 残す
- パーツは 少なく。**要素 10個 以下**

各ゲームが どんな 場所かは ART_ASSET_LIST.md の 「せかい」の 表に 書いてあります。

## 8. 進め方(おすすめ)

### 8-0. まず 下絵、それから SVG

**いきなり SVG を 書かないでください。** 先に 画像生成(images 2.0)で
下絵の PNG を 作り、それを 見ながら SVG を 書きます。

| 段 | 作るもの | 置き場所 | 役わり |
|---|---|---|---|
| 1 | 下絵 | `docs/art-ref/<名前>.webp`(512px) | 絵の 良さを 決める。**参考。アプリでは 使わない** |
| 2 | SVG | `public/art/icons/<名前>.svg` | **納品物**。軽さと 色ちがい対応を 担保する |

コードで 図形を ならべる 発想の まま SVG を 書くと、いまと 同じ 絵に なります。
先に 絵として 成立させてから 写す ―― これが 大事です。
下絵を 自動ベクター化(トレース)しては いけません(パスが 増えすぎる)。
**下絵より 単純に なるのが 正解**です。

画像生成に わたす プロンプトの ひな形は
[CODEX_ART_PROMPT.md](./CODEX_ART_PROMPT.md) に あります。

### 8-1. 出す 順

202 + 59 を いちどに 出すと レビューできません。次の 順で お願いします。

| 回 | 内容 | なぜ |
|---|---|---|
| 1 | **見本 5個**: `strawberry` `fish` `person` `lantern` `bowl` | 絵柄を 決める。ここで 方針を 合わせる |
| 2 | よく 出る 20個(一覧の 「どこで つかう」が 多い もの) | 効果が 大きい |
| 3 | そざい・りょうり 67個 | 図鑑の 見た目が 決まる |

| 5 | しぜん・けしき / どうぐ / きごう | |
| 6 | 背景 59個 | アイコンが 決まってからの ほうが 合わせやすい |

## 10. アプリ側の しくみ(できました)

**SVG は もう ゲームに 出ます。** 絵を 1つ 置くだけで その かたちが 差しかわります。

- `public/art/icons/<名前>.svg` を 置く → **それだけ**。コードの 変更は いりません
- `#MAIN` / `#DARK` は 表示の ときに ほんとうの 色へ 置きかわります
- SVG が **ない** かたちは これまでの コード描画の まま。
  だから **202個 そろうのを 待つ 必要は ありません**
- SVG の 文字は バンドルに 入るので、**オフラインでも 出ます**(fetch しません)
- 焼くのは 見せる ときに 1回だけ。いろちがい 526通りを 先に 全部 焼いたりは しません

### 見くらべ(差しかえが よく なって いるかの 判定)

```
iconsheet.html?svg=compare     上=手描きSVG / 下=コード描画 を ならべる
iconsheet.html?svg=1           SVG が ある かたちだけ
```

`?svg=compare` が この 仕事の **成果を 見る 画面**です。上下で 見くらべて、
下より 良く なって いなければ 描きなおしです。

### のこっている こと

- **パーティクル(はじける つぶ)は まだ コード描画**を つかいます。
  1つ 4px ほどなので 見た目に ひびきません
- 背景(§7)の SVG を 出す しくみは まだ。背景の 回(第6回)に あわせて 作ります

## 11. 迷ったら

- 「子供が 1秒で わかるか」で 決める。上手さより わかりやすさ
- 似た ものと まちがえそうなら、**とくちょうを 1つ 大げさに する**
  (くり= とがった さき、いも= 土の 点、ふぐ= まるい 体と とげ)
- 一覧の 「どこで つかう」を 見て、その 食べものの 実物を 思い出す
- 迷った ものは 描かずに 質問して ください。202個の うち 数個 遅れても 困りません
