# あそびかたの 伝え方

47県ぜんぶ 遊べるように なったが、**何を すれば いいのか・どう 操作するのか の
説明が どこにも ない**。その 設計と、いまの 実装の ありか。

> **状態: 段1〜6 ぜんぶ 実装ずみ。** 下の 段取り表を 見ると どこに 何が あるか わかる。

---

## 1. いま わからない こと(穴の 洗い出し)

実際に 画面を 見て 確かめた 結果。

| どこ | 状況 | 判定 |
|---|---|---|
| 県に 着いた あと | 何の 説明も ない。カードが 並ぶだけ | **穴** |
| そざいを そだてる 流れ | 「たねを まく」→ 待つ →「しゅうかく」の 順番が わからない | **穴** |
| レシピ・おまつりの つながり | そざい→めいぶつ→おまつり の 関係が どこにも 書いていない | **穴** |
| 収穫ゲーム 12種 | 画面 上部に 1行の 案内(`api.sign`)だけ。4秒で うすくなる | **弱い** |
| おまつり 47種 | 開始前に 説明モーダルが 出る(47本ぶん 文章あり) | **あるが 毎回 出て じゃま** |
| あとから 見返す | どこにも ない。忘れたら 終わり | **穴** |
| おうちのひと | ゲームの 遊び方を 知る 手段が ない | **穴** |

大きな 問題は 2つ。
**(A) ゲーム全体の 目的と 手順**が どこにも ない。
**(B) 個々の ゲームの 操作**が 文字だけで、字が 読めない 子には 届かない。

---

## 2. 設計の 考え方

4〜8歳。**字を 読ませない**のが 大前提。

> 説明を 読ませるのでは なく、**やって みせる**。

だから 3つの 層に 分ける。

| 層 | 何を 伝える | いつ 出る | かたち |
|---|---|---|---|
| 1 | この ゲームで やる こと(共通) | 初めて 県に 着いた とき 1回 | ぴっけの 3コマ |
| 2 | この ゲームの 操作 | その ゲームを 初めて 開いた とき | **ゆびマークの 実演** |
| 3 | 忘れた ときに 見返す | いつでも | ずかんの 「あそびかた」 |

---

## 3. 層1: この ゲームで やる こと(共通)

### 3-1. 初めて 県に 着いた とき(1回だけ)

ぴっけが 3コマで 教える。それぞれ 絵 + 1行。スキップ できる。

```
1. 「まずは そざいを そだてよう!」
   たねを まく → すこし まつ → しゅうかく!
2. 「そざいが そろったら めいぶつを つくろう!」
   レシピを さがす → つくる
3. 「めいぶつが できたら おまつりだ!」
   おまつりを ひらくと もやもやぐもが はれる
```

- `state.seenPrefGuide` で 1回だけに する
- 「まってる あいだは ほかの けんへ 行こう」も ここで 伝える
  (待ち時間の 意味が わからないと 手が 止まる)

### 3-2. 県ページに 常設の 「いま やること」

初回ガイドは 1回で 忘れられる。だから **いまの 状態に 合わせた 1行**を
県ページの 上に つねに 出す。地図(MapScene)に 同じ しくみが すでに あるので、
それを 県ページにも 付ける。

| 状態 | 出す 文 |
|---|---|
| そざいを 1つも まだ うえていない | 「まずは そざいを うえてみよう!」 |
| そだち中しか ない | 「そだつまで ほかの けんへ 行ってみよう!」 |
| しゅうかくできる ものが ある | 「しゅうかくできる ものが あるよ!」 |
| おせわチャンス中 | 「おせわチャンス! いそげ〜!」 |
| そざいは あるが レシピ 未取得 | 「レシピを さがして みよう!」 |
| つくれる レシピが ある | 「めいぶつが つくれるよ!」 |
| おまつりが ひらける | 「おまつりが ひらけるよ!」 |

これは **ロジックだけ**で 済む(`core/` に 純関数 + ユニットテスト)。
文章は `uiText.ts` に まとめる。

## 4. 層2: ゲームの 操作(ゆびマークの 実演)

**ここが この 案の 中心。**

### 4-1. 何を するか

ゲームが 始まった 直後、**半透明の ゆびマークが 実際の 操作を やって みせる**。
文字は 今の 1行(`api.sign`)だけ。

- タップの ゲーム → 的の 上で ゆびが トン、トン
- ドラッグの ゲーム → ゆびが すーっと 動く 軌跡を 描く
- 長おしの ゲーム → ゆびが 止まって 波紋が ひろがる
- ぐるっと 回す ゲーム → ゆびが 円を 描く
- こうごに タップ → 左右の ボタンを 交互に トン、トン

**消える 条件**: プレイヤーが 1回 操作したら すぐ 消える。
**また 出る 条件**: 5秒 何も しなかったら もう一度 出る(迷っている 合図)。

これなら 字が 読めなくても わかる。読める 子の 邪魔にも ならない。

### 4-2. データ駆動で 書く(コードに 分岐を 書かない)

CLAUDE.md の 「データ駆動」に 合わせて、**操作の かたちを 1行の データ**に する。

```ts
// src/data/howto.ts のイメージ
export type HowTo =
  | { kind: 'tap'; at: [number, number][] }        // きまった 場所を トン
  | { kind: 'tapTarget'; name: string }            // うごく 的(name)を トン
  | { kind: 'drag'; from: [number, number]; to: [number, number] }
  | { kind: 'hold'; at: [number, number]; ms: number }
  | { kind: 'swipe'; at: [number, number]; dir: 'up' | 'down' | 'left' | 'right' }
  | { kind: 'circle'; at: [number, number]; r: number }
  | { kind: 'alternate'; at: [number, number][] };  // こうごに トン

export const HOW_TO: Record<string, HowTo> = {
  chain:  { kind: 'tapTarget', name: 'mg-fruit' },
  pluck:  { kind: 'drag', from: [240, 300], to: [240, 400] },
  owara:  { kind: 'hold', at: [240, 250], ms: 1500 },
  hanagasa: { kind: 'circle', at: [240, 392], r: 70 },
  waraji: { kind: 'alternate', at: [[130, 632], [350, 632]] },
  // …収穫12 + おまつり47 = 59行
};
```

描画は `src/ui/howto.ts` の 1つの 関数が ぜんぶ 面倒を 見る。
新しい ゲームを 足す ときは **この 1行を 足すだけ**。

E2E で すでに 「どう 操作すれば 点が 入るか」を 台本に 書いてあるので、
**その 座標を そのまま 使えます**(59本ぶん すでに 判明している)。

### 4-3. おまつりの 説明モーダルは 初回だけに

いまは 毎回 全文が 出て 邪魔。次のように する。

- **初回**: いまの 説明モーダル(文章)+ そのあと ゆびマーク
- **2回目以降**: モーダルを 出さず すぐ 開始。ハイスコアだけ 短く 表示
- ゲーム中の 右上に **「?」ボタン**。押すと 説明モーダル + ゆびマークを 再表示

`state.playedGame[エンジン名] = true` で 判定する。

### 4-4. あわせて 直したい こと

いまの おまつり説明は **47件の 対応表が PrefScene の 中に べた書き**されている
(`INTROS` という 47行の Record)。これは データ駆動の 原則に 反するので、
説明文も `HOW_TO` と 同じ ところに 移す。

## 5. 層3: あとから 見返す(ずかんの 「あそびかた」)

ずかんに タブを 1つ 足す。

- **遊んだ ことが ある ゲームだけ** 並べる
- 未プレイは `？？？` + 「まだ あそんでいない」。**ネタバレ しない**
- 1つ 選ぶと 説明文 + ゆびマークの 動く 見本(実際の ゲーム画面では なく 小さな 枠の 中)
- おうちのひとも ここを 見れば 遊び方が わかる

---

## 6. ネタバレの 扱い(ご懸念への 回答)

「解放前に 操作方法が 見えると ネタバレ」への 対策。

| 出す ところ | 解放前に 見えるか | 理由 |
|---|---|---|
| 層1 県の 共通ガイド | 見える(でも 問題なし) | 手順だけで 中身の ネタバレは ない |
| 層2 ゆびマーク | **見えない** | そのゲームを 開いた 瞬間に しか 出ない |
| 層2 説明モーダル | **見えない** | 同じ |
| 層3 ずかんの 一覧 | **見えない** | 遊んだ ものだけ 出す |

つまり **「初めて 触った その場で 教える」**に 寄せると、
ネタバレ対策を 別に 作らなくて よい。一覧だけ 「遊んだ もの限定」に すれば 足りる。

### 決めごと(実装で 変わった ところ)

- **ざひょうは area ローカル**。`GAME_AREA_Y`(=52)だけ 下に ずれた いれものの 中の 位置で
  書く。ミニゲームの 定数(`ROW_Y0` など)を そのまま 写せる ため。
  E2E 台本の 画面ぜんたいの y を 写す ときは 52 を ひく。
- **47件の 対応表は 消した**。`PrefScene` に あった `INTROS`(47行)は、
  `uiText` の `introDaruma`… を **名まえの きまり**(`intro` + ゲーム名)で ひく
  `festIntro(kind)` に した。おまつりを 足す ときに さわる ファイルは data だけ。
- **おまつりゲーム名は 47県で ユニーク**。なので ずかんの 「あそびかた」は
  ゲーム名 → レシピ を 引きあてて 名まえ・絵を データから とる(あたらしい データを ふやさない)。
  しゅうかくゲームの ぶんだけ `UI_TEXT.howto.harvest` と `HARVEST_ICON` を もつ。
- **テストで 固定した こと**: 全ゲームに ゆびマークが ある / ざひょうが area の 中に ある /
  `tapTarget` の 名まえが ほんとうに `setName` されている / 全おまつりに 説明文が ある。
  → 新しい ゲームを 足して ゆびマークを 忘れたら テストで 落ちる。
- **E2E**: `__mqAdmin.skipGuides()` で 3コマを とばす(3コマ自体は verify-guide.mjs が しらべる)。
  おまつりの 説明モーダルは 初回だけ なので `d.startFest()` が 有無を 見て おす。

## 8. あとで 見なおしたい こと

1. **ゆびマークの ざひょうの こまかさ**。うごく ものを さす ゲーム
   (`tapTarget`/`dragTarget`)は じっさいの ものを 追うので ずれない。
   きまった ばしょを さす ゲームは、ゲームの わりつけを 変えたら
   `src/data/howto.ts` の その 1行も 直す こと(テストは 「area の 中か」までしか 見ない)。
2. **ずかんの 見本わく**は いま 空の そら色。ゲームの 背景も 出せると もっと わかりやすい
   (絵が そろってから。docs/ART_DIRECTION.md の 背景59枚)。
3. **おうちのひと 向けの まとめ**。いまは 「あそびかた」タブが その 役目を かねている。
   紙 1まいの 説明が ほしく なったら ここから 起こす。
